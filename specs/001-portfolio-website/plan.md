## Summary

A single-page personal portfolio website that makes an immediate "WOW" impression on
recruiters and clients. Five sections — Projects, Experience, Skills, Contact — follow
a striking hero, in an order designed to lead with proof and close with a call to action.
The site is built with Astro 6.3 (zero-JS default, Content Collections, View Transitions),
styled with TailwindCSS 4.3 (CSS-first OKLCH design tokens), and animated with Motion 12.x
(spring physics, scroll-triggered reveals). Hosted statically on Cloudflare Pages (270+ PoPs)
for sub-second FCP globally. No CMS, no server-side rendering.

## Technical Context

**Language/Version**: TypeScript 5.x — strict mode, zero type errors enforced

**Primary Dependencies**:

- Astro 6.3 — framework (zero-JS default, Content Collections, View Transitions)
- TailwindCSS 4.3 — CSS-first utility styling with OKLCH design tokens
- Motion 12.38 — vanilla JS animations (spring, scroll, inView, stagger)

**Secondary Dependencies**:

- Playwright — e2e testing (critical paths only)
- ESLint (`eslint-config-astro`) + Prettier — linting/formatting
- Wrangler — Cloudflare Pages deployment CLI
- Zod (bundled with Astro) — Content Collection schema validation

**Storage**: Content Collections (file-based JSON, build-time only) — no runtime database

**Testing**: Playwright e2e (contact form flow, navigation, a11y, mobile viewport)

**Target Platform**: Static CDN — Cloudflare Pages (270+ PoPs globally)

**Project Type**: Static web application — single page, pre-rendered at build time

**Performance Goals**:

- First Contentful Paint (FCP) ≤ 1.0s on 4G
- Lighthouse Performance ≥ 95 (mobile, simulated slow 4G)
- Lighthouse Accessibility = 100
- Total initial page weight ≤ 1.5 MB (uncompressed, excluding user media)

**Constraints**:

- GA4 included — fires unconditionally on every page view (consent assumed, no banner required)
- Self-hosted fonts only — no render-blocking Google Fonts requests
- Contact form: third-party service (TBD — host-agnostic, honeypot native, no extra JS)
- Dark theme only in v1 — design tokens structured for future light theme extension

**Scale/Scope**:

- ~5 sections of content on a single scrollable page
- ~3–10 project entries, ~3–5 experience entries, ~4–6 skill categories
- Solo developer; no CMS; content changes via code commits

## Design Direction

_This section captures the non-negotiable visual intent to guide implementation.
Specific colour values, typeface names, and motion parameters are finalised during
the task phase._

### Visual Identity

**Aesthetic**: Dark, refined, technically confident. Not developer-dark (neon on black).
Think editorial — like the opening spread of a premium design magazine. Rich deep
backgrounds, intentional negative space, typographic hierarchy as a visual element
in its own right.

**Composition**: The layout should feel custom-drawn, not grid-snapped. Overlapping
elements, deliberate asymmetry in placement, and large typographic lockups that sit
above the grid create visual tension and energy.

### Hero Section

The hero must own the full viewport on load:

- Developer name as a large-scale display typeface — the text itself IS a visual element
- A purposeful interactive/animated backdrop: options include a WebGL noise field, an SVG
  mesh gradient that shifts on cursor movement, or a letter-scramble/reveal animation
- A single line of professional context below the name
- A clear, understated scroll invitation (no "scroll down" text — a visual cue only)
- No stock imagery; no avatar in the hero

**Non-negotiable**: A first-time visitor MUST feel something within 3 seconds.

### Navigation

Persistent minimal top bar — transparent over hero, opaque on scroll. Section anchors
only. On mobile: hamburger or full-screen overlay.

### Projects Section

Cards/panels with deliberate visual differentiation per project — not a uniform grid.
Options: staggered grid, alternating featured/compact layout. Each entry is memorable.

### Experience Section

Timeline or structured list. Premium résumé aesthetic. Clear hierarchy:
role → company → dates → accomplishments. Rhythm through spacing, not heavy borders.

### Skills Section

Categories as visual anchors. Skills as legible badges. `expert` tier skills visually
differentiated through prominence/size, not numbers. Confident, not a laundry list.

### Contact Section

Simple, direct. Large inviting heading. Generous-touch-target form. Satisfying
confirmation state. Direct email as fallback.

### Motion Principles

- **Enter animations**: `inView()` scroll-triggered, staggered reveals. Subtle
  translate-Y + opacity, spring easing. Duration ≈ 0.4–0.6s.
- **Hero**: One bespoke effect — more dramatic than a fade.
- **Hover states**: `animate()` for card interactions. Precise, not rubber-band.
- **Reduced motion**: All Motion calls respect `prefers-reduced-motion`; static
  alternatives retain full content visibility.

## Google Analytics 4 (Late MVP1 Step)

> ⚠️ This supersedes spec clarification Q1. GA4 is added as one of the **final** tasks
> before public launch, after all content and core functionality is complete.

**Integration**: GA4 via `gtag.js`, loaded unconditionally on every page view. Consent is assumed — no consent banner or `localStorage` state is required.

**Implementation in `BaseLayout.astro`**:

```astro
---
const GA_ID = import.meta.env.PUBLIC_GA_ID; // e.g., "G-XXXXXXXXXX"
---
{GA_ID && (
  <>
    <script
      is:inline
      async
      src={`https://www.googletagmanager.com/gtag/js?id=${GA_ID}`}
    />
    <script is:inline define:vars={{ GA_ID }}>
      window.dataLayer = window.dataLayer || [];
      function gtag(){ dataLayer.push(arguments); }
      gtag('js', new Date());
      gtag('config', GA_ID, { anonymize_ip: true });
    </script>
  </>
)}
```

**Environment variable**: `PUBLIC_GA_ID` — set in Cloudflare Pages environment
variables (not committed to the repository). GA does not fire in local development
(variable is absent).

**CSP header update** — `public/_headers`:

```
script-src 'self' 'unsafe-inline' https://www.googletagmanager.com https://www.google-analytics.com;
connect-src 'self' https://www.google-analytics.com https://analytics.google.com https://stats.g.doubleclick.net [form-service-domain];
```

**Performance impact**: GA4's `gtag.js` is ~28 kB (gzipped). The script is loaded
with `async` to prevent blocking FCP or LCP. Lighthouse performance audits remain
reliable since the async script does not hold up rendering.
